# BGE-M3 на Intel Arc

[English version](bge-arc.md)

Этот профиль подключается явно. OpenVINO запускает закреплённый FP16-энкодер BAAI BGE-M3 и две обученные проекции на Intel GPU. Рабочий процесс запускается без сети, читает веса из каталога, смонтированного только для чтения, и принимает запросы через приватный Unix-сокет. Токенизация и агрегация лексических весов выполняются на CPU.

## Подготовка профиля

Используйте FP16-экспорт из [аппаратной проверки Project Creator](https://github.com/VolkovDani/project-creator/blob/94003dd680fbf72812f4145d1345fbb34bfa44b1/docs/intel-device-verification.md). Контрольные суммы OpenVINO IR и токенизатора должны совпасть с закреплёнными в скрипте подготовки. Для скрипта нужно локальное Python-окружение с NumPy и PyTorch. Обе библиотеки есть в использованном при проверке окружении экспорта Project Creator.

```sh
pc_dir=/absolute/path/to/project-creator
test -e models.json || cp models.example.json models.json
export MODELS_BGE_MODEL_DIR="$PWD/.bge/models/bge-m3-arc"
export MODELS_BGE_PROFILE=$(
  "$pc_dir/.npu/export-env/bin/python" -m runtime.bge.prepare \
    --encoder-dir "$pc_dir/.npu/models/bge-m3-fp16" \
    --output-dir "$MODELS_BGE_MODEL_DIR" --download-heads
)
```

Команда скачивает только две проекции из закреплённой ревизии BAAI. Для подготовки без сети используйте `--heads-dir /absolute/path/to/heads` с официальными файлами `sparse_linear.pt` и `colbert_linear.pt`. Выходной каталог должен быть новым. Напечатанный SHA-256 закрепляет веса, токенизатор, предобработку и лимиты токенов.

## Запуск

Добавьте запись в приватный `models.json` и подставьте напечатанный digest.

```json
{"name":"bge-arc","provider":"openvino-bge","base_url":"unix:///run/models-bge/runtime.sock","model":"BAAI/bge-m3","role":"embeddings","digest":"<profile SHA-256>"}
```

Предоставленный Compose-файл ожидает Intel Arc по пути `/dev/dri/renderD128`. Сверьте render node на хосте. Сохраните настройки профиля в локальном `.env`, чтобы они сохранились при перезапуске оболочки.

```sh
export MODELS_BGE_SOCKET_DIR="$PWD/.bge/run"
install -d -m 0750 "$MODELS_BGE_SOCKET_DIR"
export MODELS_BGE_UID=$(id -u)
export MODELS_BGE_SOCKET_GID=$(stat -c %g "$MODELS_BGE_SOCKET_DIR")
export MODELS_BGE_DEVICE_GID=$(stat -c %g /dev/dri/renderD128)
docker compose -f compose.yml -f compose.bge-arc.yml up --build -d
curl --fail --silent http://127.0.0.1:8317/v1/models
```

Если NPU уже подключён, добавьте `compose.bge-arc.yml` к действующему списку Compose-файлов. Если после аварийной остановки остался файл сокета, проверьте, что его рабочий процесс остановлен, прежде чем удалять этот файл.

## Использование профиля

Передавайте полный ID модели из списка. Действующий метод `POST /v1/embeddings` возвращает плотные векторы размерности 1024 и принимает до 32 текстов по 4096 токенов. Для эксперимента отправьте следующий запрос на `POST /v1/bge-m3/encode`. Этот метод принимает до четырёх текстов и требует явного списка режимов. В запросах со Sparse или ColBERT действует лимит 128 токенов на текст. Лимиты включают специальные токены.

```json
{"model":"<manager model ID>","input":["Отправить заявку."],"modes":["dense","sparse","colbert"]}
```

Ответ содержит ID модели в менеджере и одну запись на входной текст. Sparse возвращает положительные веса по ID словаря. ColBERT возвращает векторы отдельных токенов. Смена профиля эмбеддингов в Project Creator ставит требования в очередь переиндексации. Текущий поиск использует плотные векторы.

## Сравнение на Intel Arc

Замеры от 25 ноября 2026 года выполнены на ревизии Models Configurator
`4c38a401b912071e43d2ab4ba2b5f5cebebc1b7e` со встроенной графикой Intel Lunar Lake
(PCI ID `8086:64a0`, драйвер `xe`, Linux `7.0.0-44-generic`). OpenVINO 2026.4.1
подтвердил устройство `GPU.0` и профиль
`8355863b970396ca34421df3f082485ced9d2f842d92e8dd230d2df7c2bc1d53`.
Ollama 0.40.16 загрузил модель `bge-m3:567m` F16 с digest
`7907646426070047a77226ac3e684fbbe8410524f7b4a74d02837e43f2146bab` через Vulkan
и сообщил об использовании памяти GPU.

| Измерение | OpenVINO | Ollama |
| --- | ---: | ---: |
| От запуска контейнера до первого плотного вектора, медиана (разброс) | 3,11 с (3,03–3,21 с) | 2,50 с (2,41–2,65 с) |
| После прогрева, Dense, 1 текст, p50 / p95 | 12,50 / 14,35 мс | 43,40 / 45,39 мс |
| После прогрева, Dense, 8 текстов, p50 / p95 | 102,23 / 140,72 мс | 330,14 / 343,29 мс |
| После прогрева, пропускная способность Dense, 8 текстов на запрос | 73,12 текста/с | 22,92 текста/с |
| После прогрева, Dense + Sparse + ColBERT, 1 текст, p50 / p95 | 18,42 / 23,44 мс | Недоступно |
| Пиковая анонимная память контейнера | 617 МиБ | 296 МиБ |
| Пиковый рабочий набор памяти контейнера | 992 МиБ | 361 МиБ |
| Пиковый объём памяти, выделенной клиентам Xe DRM | 1 133 МиБ | 1 265 МиБ |

Холодный замер начинался с запуска нового контейнера при прогретом файловом
кеше хоста. Задержки после прогрева измерены по 20 последовательным запросам
после одного пробного вызова к Unix-сокету OpenVINO или локальному HTTP-порту
Ollama. Запрос из одного текста использовал первый пример ниже, пакет из восьми
содержал все примеры в указанном порядке. Запрос всех трёх представлений
использовал тот же первый пример. В таблице приведены максимумы памяти по трём
запускам при измерении каждые 100 мс. Рабочий набор исключает неактивный файловый
кеш. Встроенный GPU использует общую системную память. Данные контейнера и DRM
частично перекрываются, а выделения DRM отличаются от собственной оценки Ollama.

1. Администратор может изменить лимит платежа.
2. Оператор не может изменить лимит платежа.
3. Система сохраняет журнал операций в течение 30 дней.
4. Система удаляет журнал операций через 90 дней.
5. Заказ можно оплатить банковской картой.
6. Возврат средств доступен после отмены заказа.
7. Сервис возвращает ошибку E104 при повторной отправке.
8. Уведомление отправляется только после подтверждения.

Отдельная проверка через работающий менеджер сравнила три коротких русских
текста с FlagEmbedding 1.2.11 на CPU FP32 и исходной ревизией BAAI
`5617a9f61b028005a4858fdac845db406aefb181`. Минимальное косинусное сходство
плотных векторов составило 0,9999978. ID токенов Sparse совпали, максимальная
абсолютная разница весов составила 0,0005451. Минимальное косинусное сходство
векторов токенов ColBERT составило 0,9999882. Проверены первый текст из списка,
то же предложение со словом «дважды» перед точкой и «Вернуть ошибку E104
при повторной отправке».

Для постоянно запущенного сервиса на этом Arc OpenVINO оказался быстрее в
проверенных сценариях Dense и дал доступ к обеим проекциям. Ollama быстрее
возвращал первый результат и использовал меньше анонимной памяти контейнера.
Замеры охватывают короткие тексты на одном компьютере. Качество поиска и
стоимость ранжирования кандидатов дополнительными представлениями проверяются
в Project Creator. [Проверка runtime](https://github.com/VolkovDani/models-configurator/issues/9) · [Проверка поиска](https://github.com/VolkovDani/project-creator/issues/64)
