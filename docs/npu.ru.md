# Генерация на Intel NPU

[English version](npu.md)

Models Configurator запускает OpenVINO GenAI напрямую на Intel AI Boost. Приложение передаёт менеджеру сообщения и строгую JSON Schema. Менеджер проверяет выбранный профиль манифеста и обращается к локальному runtime через Unix-сокет. Project Creator формирует промпт сравнения, повторяет запрос при необходимости, сопоставляет исходники и проверяет результат. Профиль NPU предназначен для генерации. Эмбеддинги настраиваются отдельно.

## Использовать существующий экспорт Project Creator

Выполните команды в каталоге Models Configurator на машине с NPU. В примере используются имеющиеся веса Qwen2.5-7B INT4 и манифест версии 2 из соседнего каталога Project Creator. Для новой установки [подготовьте модель закреплённой версии](npu-model.ru.md) и укажите полученные пути к модели, манифест и его идентификатор.

```bash
pc_dir="$(cd ../project-creator && pwd)"
export MODELS_NPU_MODEL_DIR="$pc_dir/.npu/models/qwen2.5-7b-int4"
export MODELS_NPU_MANIFEST="$pc_dir/.npu/profile.json"
export MODELS_NPU_PROFILE="$(cat "$pc_dir/.npu/profile.sha256")"
export MODELS_NPU_UID="$(id -u)"
export MODELS_NPU_SOCKET_GID="$(id -g)"
export MODELS_NPU_DEVICE_GID="$(stat -c %g /dev/accel/accel0)"
export MODELS_NPU_SOCKET_DIR="$PWD/.npu/run"
export MODELS_NPU_CACHE_DIR="$PWD/.npu/cache"
export MODELS_NPU_LOG_DIR="$PWD/logs/npu"
install -d -m 0750 "$MODELS_NPU_SOCKET_DIR" "$MODELS_NPU_CACHE_DIR" "$MODELS_NPU_LOG_DIR"
printf '%s\n' "$MODELS_NPU_PROFILE"
```

Используйте обычную учётную запись Linux и группу сокета, участникам которой разрешён инференс. Добавьте запись в массив `models` приватного `models.json`, подставив полный хеш, напечатанный выше. Пустой шаблон есть в `models.example.json`. Хеш идентифицирует канонический манифест, включая контрольные суммы файлов модели и версии runtime.

```json
{"name":"qwen-npu","provider":"openvino-npu","model":"Qwen/Qwen2.5-7B-Instruct","base_url":"unix:///run/models-npu/runtime.sock","role":"chat","digest":"<64 lowercase hex characters>"}
```

## Запустить runtime в Docker

Пример рассчитан на нативный Linux, Ubuntu 26.04 amd64 и установленный рабочий драйвер Intel NPU. Модуль ядра, прошивку, файл устройства и четыре пользовательские библиотеки, перечисленные в `compose.npu.yml`, предоставляет хост. Доступ к NPU получает только runtime. Он работает без сети, читает веса и манифест через тома только для чтения и пишет в собственный кеш. Менеджер получает доступ к каталогу сокета на чтение. При обновлении хоста зафиксируйте версии драйверов и повторите проверку.

```bash
export COMPOSE_FILE=compose.yml:compose.npu-host.yml:compose.npu.yml
docker compose up --build -d
docker compose logs --tail=20 npu-runtime
curl -fsS http://127.0.0.1:8317/status
curl -fsS http://127.0.0.1:8317/v1/models
```

Дождитесь записи о готовности в журнале runtime и значения `loaded: true` у профиля. Скопируйте полный ID `openvino-npu.…` из списка моделей для подключения клиента. При холодном запуске проверяются хеши весов и компилируется модель. Для следующих запусков и остановок через `docker compose up -d` и `docker compose stop` сохраните переменные в текущем терминале или в приватном `.env` менеджера.

## Запустить runtime на хосте с менеджером в контейнере

Используйте те же настройки и каталоги. В одном терминале запустите runtime. Можно явно выбрать существующий интерпретатор Project Creator с подходящими версиями пакетов. Для нового окружения выполните `scripts/install-npu-runtime .npu/venv` и укажите его Python в команде ниже.

```bash
"$pc_dir/.npu/runtime-env/bin/python" runtime/npu/npu_runtime.py serve \
  --model "$MODELS_NPU_MODEL_DIR" --manifest "$MODELS_NPU_MANIFEST" \
  --profile "$MODELS_NPU_PROFILE" --socket "$MODELS_NPU_SOCKET_DIR/runtime.sock" \
  --cache "$MODELS_NPU_CACHE_DIR"
```

В другом терминале с теми же настройками выполните `docker compose -f compose.yml -f compose.npu-host.yml up --build -d`. У каждого runtime свой сокет. Каждый новый рабочий процесс проверяет закреплённые файлы, устройство и версии пакетов. Существующие каталоги весов сохраняются. Нативный процесс останавливается через Ctrl+C, контейнерный — через Compose.

## Изменить лимиты NPU в веб-панели

Откройте **Настройки моделей** и найдите профиль NPU. Загрузите его текущий закреплённый манифест, укажите входной лимит и лимит ответа и нажмите **Сохранить новый манифест**. Редактор сверяет SHA-256 загруженного манифеста с конфигурацией и меняет только два лимита. Скачанный файл называется `npu-<sha256>.json`. Допустимый диапазон входного лимита — 1–32768 токенов, лимита ответа — 1–4096. Проверьте выбранные лимиты на своём NPU.

Для применения укажите в `MODELS_NPU_MANIFEST` скачанный файл, а в `MODELS_NPU_PROFILE` — SHA-256 из его имени. Укажите этот же дайджест в профиле NPU в `models.json`, затем пересоздайте runtime и менеджер. Когда runtime сообщит о загрузке нового профиля, укажите в клиенте его новый ID из `/v1/models`. Сохраните прежний манифест и дайджест для отката.

## API и диагностика

Передавайте в `POST /v1/chat/completions` полный ID профиля, сообщения и `response_format.type=json_schema` с `strict: true`. Данный профиль использует жадное декодирование. Потоковая передача и переопределение параметров сэмплирования не поддерживаются. Верхняя граница токенов в запросе действует в пределах лимита манифеста. Слишком длинный промпт или незавершённая генерация приводят к явной ошибке. Максимальный размер запроса через приватный сокет — 65 536 байт. Прикладные проверки выполняет клиент.

Отправьте то же тело запроса в `POST /v1/chat/token-count`, чтобы проверить промпт перед генерацией. Рабочий процесс формирует тот же промпт и считает токены без генерации. Подсчёт доступен и при превышении лимита входа из манифеста. Если сериализованный запрос для сокета превышает 65 536 байт, менеджер возвращает HTTP 413 с кодом `TOKEN_COUNT_REQUEST_TOO_LARGE`. Сократите вход перед подсчётом или генерацией. [API проверки лимита токенов](../README.ru.md#проверить-лимит-токенов-чата)

Отключение клиента во время выполнения запроса останавливает рабочий процесс. Следующий запрос генерации или подсчёта токенов дожидается остановки предыдущего процесса. Затем при проверке готовности среда может заново загрузить тот же проверенный профиль. Панель состояния читает метаданные без загрузки весов и инференса. Для запросов чата менеджер возвращает технический `X-NPU-Call-ID`, по которому можно найти запись в журнале рабочего процесса. При ошибке провайдера наружу передаются только коды из разрешённого списка. Для проверки запуска, отмены и восстановления используйте журналы runtime и `logs/npu/runtime-lifecycle.jsonl`. При аварийном завершении, таймауте генерации или изменении артефакта требуется вмешательство оператора.

В Project Creator можно совместить этот профиль с локальными эмбеддингами на Arc. В приватном окружении приложения задайте клиентскую сеть менеджера, тип генератора `openai-compatible`, адрес `http://models-configurator:8317/v1` и полный ID модели. При переключении с прежней локальной установки NPU выполните `./project-creator setup --device arc --switch-device`. См. [настройку клиента](https://github.com/VolkovDani/project-creator/blob/develop/docs/setup-cli.md).

На Intel Core Ultra 7 268V (Intel AI Boost, Ubuntu 26.04.1, пользовательский драйвер и прошивка Intel 1.38.0, загрузчик Level Zero 1.32.0) контейнер без сети под непривилегированным пользователем загрузил имеющийся профиль Qwen INT4 `f36b13cbad8752f05d141eba6f817045986a615d13ffb5688fe417faeebca271`. При одинаковых входах полностью совпали результаты трёх примеров Project Creator с результатами прежнего нативного рабочего процесса. Счётчик занятости NPU вырос при каждой генерации. После разрыва соединения процесс остановился за 0,58 с, пассивная проверка показала выгруженную модель, а следующий запрос вернул ожидаемый результат через 19,76 с после отмены. На прежнем нативном маршруте восстановление и получение результата заняли 15,52 с. Это отдельные наблюдения на данном устройстве.
