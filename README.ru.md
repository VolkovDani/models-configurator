# Models Configurator

[English version](README.md)

Сервис для приложений на одном компьютере, которым нужны генерация со структурированным ответом или эмбеддинги. Go-сервер предоставляет панель состояния, редактор настроек, версионированный API и адаптеры для OpenVINO NPU, Ollama и OpenAI-совместимых провайдеров. Каждый запрос выбирает один профиль. Автоматического переключения провайдеров нет.

## Запуск с пустым списком моделей

Для Linux и Docker Compose 2.24+ выполните в ветке разработки:

```bash
test -e models.json || cp models.example.json models.json
docker compose up --build -d
curl http://127.0.0.1:8317/v1/models
```

Панель открывается по адресу http://127.0.0.1:8317/. В этой конфигурации запускается только менеджер. Для запуска из исходников используйте Go 1.26+ и команду `go run ./cmd/models-configurator -config models.json`. По умолчанию сервер на хосте слушает loopback.

## Добавление моделей

Для локального инференса на CPU явно запустите Ollama и загрузите нужные веса. Последняя команда выводит полные SHA-256-манифесты скачанных моделей в виде контрольных сумм:

```bash
docker compose --profile cpu up -d ollama
docker compose exec ollama ollama pull qwen2.5:7b
docker compose exec ollama ollama pull bge-m3:567m
docker compose exec ollama sha256sum /root/.ollama/models/manifests/registry.ollama.ai/library/{qwen2.5/7b,bge-m3/567m}
```

Отредактируйте приватный `models.json`. Укажите тег Ollama явно, включая `:latest`, если он используется. Подставьте полные контрольные суммы и оставьте только нужные записи. Адрес внешнего провайдера дан для примера. Выберите конкретное развёртывание и его версию.

```json
{
  "models": [
    {"name":"local-chat","provider":"ollama","base_url":"http://ollama:11434","model":"qwen2.5:7b","role":"chat","digest":"<full-qwen-sha256>"},
    {"name":"local-embed","provider":"ollama","base_url":"http://ollama:11434","model":"bge-m3:567m","role":"embeddings","digest":"<full-bge-sha256>"},
    {"name":"hosted-chat","provider":"openai-compatible","base_url":"https://provider.example/v1","model":"deployment-v1","revision":"snapshot-1","role":"chat","key_env":"HOSTED_API_KEY"}
  ]
}
```

Для провайдера с авторизацией задайте указанную переменную в приватном `providers.env` для Compose или в окружении процесса при запуске на хосте. Для передачи ключей и содержимого по недоверенной сети используйте HTTPS. После изменения конфигурации или ключа пересоздайте менеджер командой `docker compose up -d --force-recreate models-configurator`. При замене весов внешнего развёртывания оператор обновляет его ревизию. Менеджер проверяет digest Ollama до и после инференса. Локальные веса хранятся в постоянном томе Ollama менеджера.

## Настройки в веб-панели

Откройте **Настройки моделей** из списка моделей. Задайте число одновременных запросов, измените имена профилей и выберите, какие из них доступны клиентам. Для Ollama можно выбрать установленную локальную модель с закреплённым дайджестом и назначить диалог или эмбеддинги, если модель поддерживает эту роль. У профилей выбора варианта закреплены модель и назначение. У диалоговых профилей Ollama доступны размер контекста, лимит ответа, температура и Top P. Параметры, явно указанные клиентом, имеют приоритет над значениями по умолчанию.

Нажмите **Сохранить файл настроек** и поместите скачанный `model-settings.json` рядом с `compose.yml`. Добавьте `compose.settings.yml` к своим файлам Compose и пересоздайте `models-configurator`. При запуске без контейнера укажите путь к файлу в `MODELS_SETTINGS_PATH`. Файл настроек имеет приоритет над `MODELS_MAX_PARALLEL_REQUESTS`. При запуске менеджер сверяет настройки с текущим списком профилей. После изменения списка сохраните новый файл настроек или запустите менеджер без него. Чтобы восстановить прежние настройки в Compose, уберите `compose.settings.yml` и пересоздайте менеджер.

Провайдеры, адреса и ссылки на ключи задаются в основном `models.json`. Редактор сохраняет отдельный файл, который применяется при перезапуске. После перезапуска проверьте `/v1/models` и обновите ID в настройках клиентов, если они изменились. [Изменение лимитов NPU](docs/npu.ru.md#изменить-лимиты-npu-в-веб-панели).

## Подключение приложений

Откройте [Swagger UI](http://127.0.0.1:8317/docs/) из панели состояния или напрямую, чтобы посмотреть схемы и примеры и выполнить пробный запрос. Скачайте [OpenAPI JSON](http://127.0.0.1:8317/openapi.json) для импорта контракта в клиентский инструмент. Файлы интерфейса входят в поставку сервиса и доступны без интернета.

Возьмите неизменяемый ID профиля из `GET /v1/models` и передайте в поле `model`. Для клиентов на хосте базовый адрес — `http://127.0.0.1:8317/v1`. Контейнеры могут подключиться к сети `models-configurator-clients` и использовать `http://models-configurator:8317/v1`. Подключайте только доверенные приложения: в этой сети доступны все настроенные профили, включая платные внешние. В Project Creator выберите среду openai-compatible для каждой активной роли, укажите ID её профиля и добавьте `PROJECT_CREATOR_MODELS_NETWORK=models-configurator-clients` в приватную конфигурацию.

| Метод | Назначение |
| --- | --- |
| `GET /v1/models` | Список настроенных профилей без обращения к провайдерам. |
| `POST /v1/chat/completions` | Генерация без стриминга с возможностью задать строгую JSON Schema. |
| `POST /v1/chat/token-count` | Подсчёт или оценка токенов на входе и получение лимитов входа и ответа до генерации. |
| `POST /v1/embeddings` | Вещественные векторы для входных текстов в размерности выбранного профиля. Для Project Creator нужны 1024 компонента. |
| `GET /status`, `GET /` | Доступность, метаданные и время проверки. Панель обходится без инференса. Для Ollama видны отдельно наличие модели на диске и загрузка в память. |

Пример второго клиента на том же хосте с настроенным ID эмбеддингов:

```bash
curl -sS http://127.0.0.1:8317/v1/embeddings -H 'Content-Type: application/json' \
  -d '{"model":"<embedding-profile-id>","input":["hello"],"encoding_format":"float"}'
```

[Локальные модели выбора](docs/decision-models.ru.md) поддерживают System One D3 и Laya.

### Проверить лимит токенов чата

Отправьте в `POST /v1/chat/token-count` тело предполагаемого запроса на генерацию с полным ID профиля, сообщениями, схемой ответа и лимитом ответа, если они заданы. В ответе возвращаются `model`, `input_tokens`, `max_input_tokens`, `max_completion_tokens` и `exact`. Подсчёт может пройти успешно, даже если вход превышает лимит. Перед генерацией клиент может сократить контекст и повторить подсчёт.

- OpenVINO NPU локально применяет закреплённый шаблон чата и токенизатор и возвращает `exact: true`. Передавайте строгую JSON Schema и опускайте параметры сэмплирования. Лимит входа задан в манифесте. Запрошенный лимит ответа ограничен значением из манифеста. [Лимиты и диагностика NPU](docs/npu.ru.md#api-и-диагностика)
- Ollama с явно заданным `ollama_chat.context_tokens` возвращает `exact: false`. Оценка использует число байт в сообщениях и необязательной схеме с запасом на форматирование чата. Из размера контекста вычитается запрошенный или заданный по умолчанию лимит ответа. Для типовых шаблонов оценка сделана с запасом. При генерации действуют фактические ограничения модели.
- Профили Ollama без явного размера контекста или без места для резерва ответа, а также профили OpenAI-compatible возвращают HTTP 501 с кодом `TOKEN_COUNT_UNSUPPORTED`. Если подсчёт недоступен, используйте резервную проверку на стороне клиента. Подсчёт обходится без генерации и обращения к внешним провайдерам.

## История вызовов моделей

Откройте **Историю вызовов** с панели состояния или перейдите по адресу http://127.0.0.1:8317/history?lang=ru. В истории видны время начала (UTC), закреплённый профиль модели и провайдер, операция, результат, статус HTTP и длительность вызова без ожидания в очереди. Чтобы посмотреть более ранние вызовы, прокрутите страницу вниз или нажмите **Загрузить ещё**.

Над таблицей истории появится график **Длительность вызовов**. Выберите тип использования, чтобы сравнить профили моделей для этой операции. Каждая точка показывает время начала (UTC) и длительность (мс) одного вызова. В легенде указаны профили моделей, HTTP-метод и путь. При подгрузке более ранних вызовов точки добавляются на график. Recharts встроен в сервис, поэтому график работает локально.

Менеджер записывает запросы на генерацию, эмбеддинги, выбор варианта и кодирование BGE-M3 после выхода из очереди и передачи адаптеру. Отказы и ошибки отражаются в истории. Подсчёт токенов, проверки доступности, некорректные запросы и запросы, отклонённые или отменённые в очереди, в неё не попадают. История содержит только служебные сведения. Тексты запросов и ответов, тексты ошибок провайдера, ключи, идентификаторы клиентов и счётчики токенов не сохраняются. Как и остальная часть локального сервиса, история доступна приложениям с доверенным сетевым доступом к менеджеру.

Для чтения из программы используйте `GET /history.json`. В поле `calls` возвращается до 50 вызовов, начиная с последней записи. Если в ответе есть поле `next_before`, передайте его значение в `?before=<next_before>`, чтобы получить более ранние вызовы.

Последние 10 000 записей доступны после перезапуска. Compose хранит их в томе `model_history`, который сохраняется при пересоздании контейнера. При запуске на хосте файл по умолчанию находится по пути `logs/model-history.jsonl` относительно рабочего каталога. Другой путь можно задать переменной `MODELS_HISTORY_PATH`. Для каждого процесса менеджера нужен отдельный файл. Если после запуска не удаётся записать вызов, менеджер пишет ошибку в журнал и возвращает результат инференса.

## Параллельные запросы

По умолчанию менеджер выполняет один запрос на инференс или подсчёт токенов за раз. Чтобы две независимые среды могли обрабатывать запросы одновременно, задайте переменную в приватном `.env` менеджера и примените её командой `docker compose up -d models-configurator`. При запуске на хосте экспортируйте переменную перед стартом сервера.

```dotenv
MODELS_MAX_PARALLEL_REQUESTS=2
```

Выберите положительное целое число с учётом возможностей устройства и провайдеров. Каждый сокет OpenVINO обслуживает один запрос за раз, даже если на него указывают несколько профилей. Пока один запрос ждёт освобождения сокета, запрос к свободной среде может начать работу. В очереди одного процесса менеджера могут ждать до 128 запросов. Когда очередь заполнена, менеджер возвращает HTTP 429. Ожидание входит в общий лимит в две минуты. Если клиент отключится в очереди, менеджер снимет его запрос.

## Intel NPU

Рабочий процесс OpenVINO можно запустить в Docker или на хосте и выбрать его закреплённый профиль генерации в доверенном клиенте менеджера. Существующий экспорт Project Creator подключается на чтение. При новой установке можно скачать зафиксированную версию Qwen с Hugging Face и экспортировать её без сети. [Настройка NPU](docs/npu.ru.md) · [Подготовка модели](docs/npu-model.ru.md)

[Запуск BGE-M3 на Intel Arc](docs/bge-arc.ru.md) поддерживает плотные эмбеддинги и экспериментальные представления Sparse и ColBERT.

Детерминированные проверки запускаются командами `go test -race ./...`, `go vet ./...`, `python3 -m unittest discover -s runtime/npu` и `python3 -m unittest discover -s tests`.

### Пересборка графика истории

Готовый бандл включён в репозиторий, поэтому сборки Go и Docker могут отдавать график без доступа к сети. Чтобы обновить бандл после изменений исходников графика, используйте Node.js 26 и Bun 1.4.4.

```bash
cd frontend
bun install --frozen-lockfile
bun run format:check
bun run typecheck
bun run test
bun run build
```

Добавьте в коммит пересобранный бандл и уведомления о лицензиях в `internal/status/chart/`. CI проверяет, что оба файла соответствуют исходникам и lockfile.
